# M3 配色系统（动态主题）

> 单一真源：`shared/m3-theme.ts`。改配色先改这里，再跑 `npm run gen:m3-tokens`。
> 本文档描述**当前实现**；旧文档 `doc/archive/LumiLuna设计指南v1.md` 里的色值块已过期，以本文为准。

## 1. 配色口径（硬性约定）

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| Variant | **Tonal Spot** | 低-中鲜艳度；主、次、第三色均由 MCU 2025 实现生成，不套用旧版固定色相偏移公式 |
| SpecVersion | **2025** | M3 Expressive 的 color spec（MCU 0.4.0 起支持）。surface/primary 的 tone 曲线与 2021 不同 |
| Platform | **phone** | 2025 spec 里 phone / watch 是两套 tone 曲线。桌面端用 phone（watch 是为圆形小屏压缩的，深色 surface 会压到 tone 0） |
| ContrastLevel | **0 = standard** | MCU 的 -1…1 标尺，0 即设计规范的标准对比度（不是 `ContrastLevel.medium`，那档是 high） |

以上四项写死在 `M3_SCHEME` 常量里，且有单测守卫（`src/utils/__tests__/m3Theme.test.ts`）。

产品表面色阶（`SURFACE_CHROMA` / `SURFACE_TONES`）：

- 浅色背景 / surface 使用 HCT tone 96，目标彩度 12；深色使用 tone 10、目标彩度 10。彩度不超过种子本身，灰色种子不会被强行染色。
- 卡片使用同色相的独立亮度层级，不在组件中叠加半透明色；七种预设明暗模式下，正文及次要文字在所有产品表面上的对比度均由单测验证 ≥ 4.5:1。
- 这是产品对表面颜色的定制，不声称等于 MCU 默认表面值。`schemeFromSeed()` 保留官方原始输出；`cssTokensFromSeed()` 才应用有色表面，主 / 次 / 第三强调色与文字角色保留官方算法。

## 2. 一次颜色更新的完整链路

```
种子色（设置页 / 系统强调色 UDA）
   └─ settings.resolveSeed()
        └─ applySeedColor(seed, dark)          src/utils/dynamicTheme.ts
             └─ cssTokensFromSeed()            shared/m3-theme.ts   ← 算法在这里
                  ├─ new SchemeTonalSpot(...)  MCU 0.4.0
                  ├─ TonalPalette             产品表面色阶
                  └─ documentElement.style.setProperty('--md-sys-color-*', hex)
```

写入的是 **行内样式**，优先级高于任何选择器，因此 `theme.css` 的 `[data-theme="dark"]` 段会被整体覆盖 —— 这是设计意图（静态段只是首屏兜底）。

顺序约束（`settings.resolveTheme()` 里，不能调换）：

1. `clearSeedTokens()` —— 清掉上一次的行内值
2. `applySkin(...)` —— 皮肤令牌/CSS 写入
3. `applySeedColor(...)` —— 种子色最后写，覆盖皮肤里同名的值

## 3. 令牌清单（56 个角色）

覆盖 MCU 2025 spec 在 phone 平台暴露的**全部**颜色角色，外加 3 个项目语义色：

- 主色系：`primary` / `primary-dim` / `on-primary` / `primary-container` / `on-primary-container` / `inverse-primary`
- `*-dim`（**2025 spec 新增**，2021 没有）：用于「强调但不抢主色」的次级填充
- `fixed` 系列 12 个：`primary-fixed` / `primary-fixed-dim` / `on-primary-fixed` / `on-primary-fixed-variant` + secondary / tertiary
- 表面系：`surface` / `surface-dim` / `surface-bright` / `surface-container-{lowest,low,,high,highest}` / `surface-variant` / `surface-tint`
- 语义扩展（**不属于 M3 角色表**）：`success` / `warning` / `link`，见 `ACCENT_ROLES`
- `scrim` 被 `TOKEN_OVERRIDES` 改成**半透明**（`rgba(0,0,0,.7/.85)`）：项目里 `scrim` 直接当蒙层底色用，纯黑会把内容盖死

## 4. 静态兜底是**生成**的

`src/tokens/theme.css` 里的两个色令牌段由 `scripts/gen-m3-tokens.mjs` 生成：

```bash
npm run gen:m3-tokens      # 重写 theme.css 的色令牌段
npm run verify:m3-tokens   # 只校验（CI / 单测）
```

段首尾有标记 `/* ---- M3 Color Tokens (generated) ---- */` … `/* ---- /M3 Color Tokens ---- */`，生成器只替换标记之间的内容。

**为什么必须生成**：本次改造前，`theme.css` 手抄的 34 个令牌与 MCU 算法输出全面对不上（例如 `--md-sys-color-surface-container-high` 写成了偏黄的 `#eceee0`，算法给的是 `#e6e8f0`）。手抄一定会漂移，所以静态段也走算法。

单测 `m3Theme.test.ts` 会逐令牌比对 `theme.css` 与 `defaultScheme()`，手改必红。

## 5. 组件层怎么用

- **CSS 里**：一律 `var(--md-sys-color-*)`，禁止写死色值。
- **CSS 里要半透明色**：`color-mix(in srgb, var(--md-sys-color-x) 15%, transparent)`，不要写 `rgba(...)`。
- **canvas / SVG / 第三方播放器（拿不到 CSS 变量）**：调 `readPrimaryHex()`（`src/utils/dynamicTheme.ts`）。
- **Electron 主进程**（窗口首帧底色）：`defaultScheme(dark)['--md-sys-color-background']`，见 `electron/windows.ts` 的 `bootBackground()`。

### 不跟主题走的颜色（有意例外）

| 位置 | 原因 |
| --- | --- |
| 绘画调色板 `DrawingBoard.vue` 的 `PALETTE` | 用户选色画画的场景，色板必须稳定；换主题不该改用户的用色习惯 |
| 阅读器底色 `BookReader.vue` 的 `READER_THEMES` | 排版底色要纸感（深色/浅色/羊皮纸/护眼绿），跟种子色变会让正文变彩色 |
| `sponsorBlock.ts` 的分类色 | 对应 SponsorBlock 官方分类图例，是外部协议的一部分 |

## 6. 皮肤与配色

皮肤白名单（`skinSchema.ts` 的 `COLOR_TOKENS`）与内核角色表对齐，**有意排除**：

- `--md-sys-color-scrim` / `--md-sys-color-shadow`：蒙层与投影，皮肤改色只会让界面糊掉
- 其余全部角色（含 `*-dim`、`fixed`、`success/warning/link`）皮肤都可以覆盖

皮肤声明的 `manifest.seedColor: true` 时，种子色生成的整套令牌会**最后**内联写入，覆盖皮肤同名令牌。

## 7. 已知上游缺陷

`@material/material-color-utilities@0.4.0` 的 `dynamiccolor/color_spec_2025.js` 里有一行缺 `.js` 扩展名的相对导入：

```js
import { DynamicColor, extendSpecVersion } from './dynamic_color'   // 应为 './dynamic_color.js'
```

Vite / esbuild 打包不受影响（它们会自动补扩展名），但 **Node ESM 解析会直接失败**，表现为 vitest 里任何 import 本内核的测试都报 `Cannot find module ...`。

绕法见 `vitest.config.ts` 的 `server.deps.inline`。上游修好后可以删掉那段配置。
